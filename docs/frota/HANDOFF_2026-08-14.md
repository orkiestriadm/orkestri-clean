### Não use `git status` no servidor para saber o que está publicado

Vai enganar. O `deploy.sh` materializa o ref com
`git checkout <ref> -- backend frontend`, que atualiza árvore e índice mas
**deliberadamente não move o HEAD**. Depois de um deploy bem-sucedido, homologação
mostra isto:

```
HEAD:                         28aff9c        ← antigo, e continua antigo de propósito
git status -- backend:        M backend/...  ← índice contra esse HEAD velho
git diff origin/<branch>:     (vazio)        ← a árvore É o ref
```

No modelo deste script a árvore do servidor é a materialização de um ref, e o
HEAD de lá não significa nada. **Quem responde "o que está publicado" é
`scripts/verificar-paridade.sh`**, não o `git status`.

Eu mesmo caí nessa e escrevi na primeira versão deste documento que publicar
"alinha HEAD e árvore" — não alinha, e perseguir o HEAD é perder tempo.

### Publicar

O padrão do script é `origin/main`, e esta branch não está lá. Passe o ref:

```bash
bash scripts/deploy.sh homologacao origin/claude/frotas-manutencoes-corretivas-9f4103
```

O escopo é só `backend frontend`. O que legitimamente difere por ambiente
(compose, `.env`, nginx) mora fora dessas pastas, de propósito, e não é tocado —
por isso a marca de homologação sobrevive ao deploy.

## A regra central: o farol é derivado, não armazenado

Isto é o que mais custou caro na sessão e vale entender antes de mexer.

**`veiculos.status` não diz se o veículo está rodando.** É um campo que alguém
precisa editar à mão no cadastro, e ninguém edita. Na base real de homologação os
116 veículos estão todos como `ativo` — **inclusive os 7 que estão na oficina**
com OS imobilizante aberta.

O estado operacional real vem das **ordens de serviço abertas** e da **revisão
vencida**, e é calculado por `farolDoVeiculo()`:

| Farol | Significado | De onde vem |
|---|---|---|
| `parado` | não pode operar | OS aberta com `imobiliza = true` |
| `operandoComAvaria` | roda com defeito | OS aberta sem imobilizar **ou revisão atrasada** |
| `operando` | normal | nada aberto |
| `foraDeOperacao` | vendido, sinistrado, inativo | aí sim, `veiculos.status` |

`veiculos.status` continua valendo **só** para a última linha — situações que não
nascem de OS.

**Nunca reimplemente essa regra.** Chame `statusFrota()`. Explicação na seção
seguinte, que é a história de eu ter feito exatamente isso e errado.

## O que mudou hoje (14/08/2026)

### 1. Dashboard contradizia o Farol

Sintoma que o usuário reportou, com dois prints lado a lado:

```
Dashboard: 0 em manutenção, 100% de disponibilidade
Farol:     7 parados, 30 com avaria, 94% rodando
```

Não era dado faltando. A dashboard contava `veiculos.status === "manutencao"` —
o campo que ninguém edita.

**Primeira correção, que estava errada:** reusei `farolDoVeiculo()` dentro da
dashboard, mas passei `{}` no parâmetro de sinais. O farol também fica amarelo
por **revisão atrasada**, não só por OS. Resultado: 17 com avaria na dashboard
contra 30 no Farol — **treze veículos sumiam**.

**Correção final:** a dashboard **chama** o Farol em vez de imitá-lo.

```ts
// backend/src/modules/frota/frota.module.ts  (~2341, em FrotaDashboardController)
const totaisFarol = (await this.relService.statusFrota(orgId, {})).totais;
const emManutencao = totaisFarol.parado;
const comAvaria = totaisFarol.operandoComAvaria;
// "Ativos" é o que roda: operando + operando com avaria. Um veículo com defeito
// continua rodando — contá-lo fora faria o número despencar assim que alguém
// registrasse a primeira avaria.
const ativos = totaisFarol.operando + totaisFarol.operandoComAvaria;
```

O controller já recebia `relService` no construtor, então não custou ligação
nova. **Agora não é que os números batem — é que não podem divergir**, porque há
uma fonte só.

Atenção às chaves: `ContagemFarol` é **camelCase** (`operandoComAvaria`), não
snake_case. Errei isso e o build pegou.

Resultado provado em homologação, os cinco números:

| | Antes | Agora |
|---|---|---|
| Em manutenção | 0 | **7** |
| Com avaria | *não existia* | **30** |

## Como testar sem HTTP nem autenticação

Padrão que funcionou bem e economiza muito tempo: instanciar o controller
direto no container, com o Prisma real.

```js
const { FrotaModule } = require("/app/dist/modules/frota/frota.module.js");
const Dash = Reflect.getMetadata("controllers", FrotaModule)
  .find(c => Object.getOwnPropertyNames(c.prototype).includes("executivo"));
const svcReal = new (require("/app/dist/modules/frota/frota-relatorios.service.js")
  .FrotaRelatoriosService)(prisma);
const inst = new Dash(prisma, svcReal);
const kpis = (await inst.executivo(req, {})).kpis;
```

**Armadilha que me custou um ciclo:** eu injetava stubs em todas as dependências,
e o stub devolvia `null` para qualquer método. Quando a dashboard passou a
chamar `statusFrota()`, o teste quebrou com `Cannot read properties of null` —
**erro do teste, não do código**. Dependência de que o resultado depende tem que
ser real.

Roda assim:

```bash
ssh planner@10.192.4.123 "docker cp /tmp/prova.js orkestri_api:/app/p.js && docker exec -w /app orkestri_api node p.js; docker exec orkestri_api rm -f /app/p.js"
```

## Coisas que mordem

- **Tailwind purga classe dinâmica** (`w-${size}` não vira CSS). E `.btn`
  (`padding: 10px 20px`) ganha das utilities do Tailwind.
- **Coluna fixa precisa de fundo opaco** — `--bg-hover` é translúcido e o
  conteúdo aparece por baixo.
- **O catálogo de permissões é semeado por código** em `auth.service.ts`
  (`ALL_PERMISSIONS`, `seedPermissionsAndRoles`). `DELETE` em SQL é desfeito no
  próximo restart da API. Corrija na fonte.
- **O schema de homologação não é o do git** — `git checkout -- schema.prisma`
  apaga campos que só existem lá (`ownerId`, `AlertaRegra`) e quebra endpoint em
  runtime, sem erro de build.
- **Delegate do Prisma é `chamadoComentario`**, não `comentarioChamado`.
- **Comentário JSX em posição de expressão** (`{/* */}` logo após `) : (`) dá
  "Unexpected token". Use `/* */`.
- **Guarda de idempotência tem que ser string distintiva.** Duas vezes minha
  guarda era subconjunto do texto antigo e o patch pulou em silêncio.
