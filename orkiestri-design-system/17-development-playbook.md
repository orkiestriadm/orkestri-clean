# ORKIESTRI
## Development Playbook
Version 1.0

---

# Objetivo

Este documento define como todo desenvolvimento deve acontecer dentro da Orkiestri.

Não define apenas código.

Define metodologia.

Toda tarefa deve seguir exatamente este fluxo.

---

# Regra Número 1

Nunca comece escrevendo código.

Sempre comece entendendo o problema.

# Descoberta

Antes de qualquer implementação responder:

Qual problema resolve?

Quem utilizará?

Existe algo parecido?

Pode reutilizar componentes?

Existe documentação?

# Componentização

Sempre perguntar:

Este componente poderá ser reutilizado?

Se sim,

Criá-lo como componente independente.

---

# Implementação

Sempre:

Começar simples.

Implementar.

Testar.

Refatorar.

---

Nunca:

Escrever código enorme.

# Revisão

Melhorar nomes.

Melhorar tipagem.

Melhorar acessibilidade.
